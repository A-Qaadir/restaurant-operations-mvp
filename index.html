Mandatory release gate: This browser demo does not implement production security. The full project checklist below must be implemented and verified before release.
View mandatory security checklist
Secrets and Git

Keep API keys out of source code, use environment variables or a secrets manager, scan Git history, and rotate exposed credentials.

Authentication

Secure login, strong password hashing, protected admin accounts, and rate-limited login attempts.

Permissions

Enforce roles and restaurant-level data isolation on the server. One restaurant must never access another restaurant’s records.

Database and APIs

Parameterized queries, input validation, restricted database privileges, row-level security where applicable, and minimal API responses.

Web protection

XSS prevention, CSRF protection where relevant, restrictive CORS, secure session cookies, and security headers.

Uploads and files

Validate file type and size, restrict access, store uploads safely, and prevent executable uploads.

Infrastructure

HTTPS, disabled production debug mode, secure configuration, dependency scanning, and protected administrative endpoints.

Abuse and cost

Rate limits, bot protection where appropriate, usage monitoring, and spending alerts or caps for paid services.

Verification

Automated security tests, dependency checks, access-control tests, and a documented release checklist.

Controls must match the chosen technology. A public client key is acceptable only when designed for client use and paired with correctly enforced access policies. Privileged service credentials must never reach the browser. HTTPS and authentication alone are not sufficient.
